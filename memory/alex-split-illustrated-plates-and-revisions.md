## Generated art versus animation

Only workshop/drafting raster plates remain active from image generation. Original sprites, real logos, UI, tools and animated props are rendered separately in React/SVG/Remotion. There is no generated-video motion, no depth-map animation and no live-action B-roll in this delivered cut. A generated engine cutout was an unsuccessful experiment, not a recommended final asset. See exact prompts and retained/rejected status in the evidence pack.

## Review and delivery lessons

- Keep revision-specific scene maps and cue manifests synchronized. In V26 the intent manifest was regenerated from the current **40** cues; an earlier 41-cue list had become stale. The isolated-stem check uses the current cue list.
- V24 failed first-frame brightness and repeated bright keyboard cues. V25 made the opening terminal/set bright before the Enter-triggered dark-mode change and replaced the redundant keyboard cue. This is not permission for an unrelated white flash or a brighter whole movie.
- For a music-only request, copy the original video stream and replace audio. V26 verifies identical encoded H.264 stream, voice stem, effects stem and all scene/caption source; music changes throughout the reel.
- Rebuild the source archive after the last change. Preserve canonical Drive IDs when replacing files, then compare synced metadata sizes and hashes. State that this is DriveFS metadata verification, not an independent download/playback check.
- Review here comprised rendered samples, native-size checks and measured audio/output audits. No uninterrupted human playback/listening was performed. This is a documented review limitation, not a new workflow exemption.
- Delivered does not mean creatively approved. There is no supplied retention study for this style. The September 21 request authorizes documenting an alternative, not claiming performance superiority.
