# X144: a continuous conveyor was still too repetitive

Alex explicitly rejected the delivered X revision: even after 22 seconds, animations needed
much more motion and had to be faster paced and more visually interesting **throughout**.
This refers to X, not the two SETUP trial hooks. R3's passing motion checks did not make it
an approved visual or retention reference.

## What remained wrong

R3 replaced a repository/star hold with a working converter, but kept essentially the same
wide conveyor composition across the introduction, format list and Markdown output: almost
ten seconds with the same machine, page silhouette and direction of travel. Rotating wheels,
small page movements and a walking sprite made the image change without creating enough
new events. Later sections returned to page-and-chat-panel layouts. The useful operation
was clearer, but the visual rhythm remained predictable.

This is a visual diagnosis consistent with the user's feedback, not a measured causal
explanation of audience behavior. No new retention chart was supplied.

## Correction to the production rule

- **Continuity is causal continuity, not a requirement to hold one camera setup.** Carry
  semantic content forward while changing the operation and staging: strip, sort, bind,
  release, unlock, connect, convert and dispatch.
- A request to improve “after 22 seconds throughout” includes every later scene, the result
  and CTA. Inspect the lead-in too; R4 again begins at frame 617 (20.5667s).
- Give each beat short, complete operations with readable travel, contact and reaction.
  Follow a completed action with a consequence. Speeding an entire timeline or increasing
  continuous camera zoom cannot fix a repetitive concept.
- Animate the semantic objects. A returned token stack, stripped outer shell, unfurling
  spreadsheet and locking cable each have a reason to move. Background gears alone do not.
- Different formats need different structures: a sheet stack, spreadsheet accordion,
  presentation fan and video filmstrip. Do not put a new file extension on the same PDF.
- Align the hero format with the actual word timing. Initial R4 review caught format changes
  running ahead of the narrator; corrected onsets are near frames 763, 781, 795, 811 and 829.
- Clear the previous apparatus when its job is finished. Initial R4 review caught the press
  still dominating after ejection and a gear overlapping the output; the press now retires
  while Claude catches and carries the clean core.
- Keep the original face visible and the task legible at phone size. Fast motion needs
  staging and hierarchy, not more labels, particles or arbitrary shaking.
- Match Foley to the final event times. R4 uses 65 cues across 45.667s (~1.42/s), with the
  existing prepared narration unchanged. More visual motion does not require an impact
  on every frame or an indiscriminately louder mix.

A second visual critique rejected the intermediate evidence-rail diagram even though it
passed motion. The final structure scene uses disordered key teeth that align, an insertion
and turn, an opening iris, and a delivered answer. Desktop conversion was also enlarged
and Claude moved aside so the operation remains legible at phone size.

## Review and delivery

Review the first, middle and last portion of each revised scene; compare contact sheets
and motion profiles against the rejected cut. Run the existing technical gates on the final
encoded MP4. Keep those results separate from creative judgment and audience performance.
The final MP4 must be a standalone Drive video at the canonical X ID; source ZIP is secondary.
