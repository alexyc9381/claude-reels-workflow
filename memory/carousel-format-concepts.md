## ⭐ REVISION-AGENT PASS (2026-07-17, 21 agents / 118 blockers) — what it taught
Ran a Workflow: 2 hook agents (10+ candidates each vs the 10-check gate) → 1 judge → 17 FRESH per-slide vision critics → 1 synthesis. Worth repeating on every carousel. **But critics do NOT know the canon — verify every flag against the source before acting.**
- ⛔ **REJECTED, and why (a critic majority can still be wrong):** "four legs = a render bug" → the 4-leg critter is the CANONICAL Mascot in ~60 shipped reels, `ClaudeFactoryReel.tsx` included. "✓ is an emoji" → [[reel-no-emoji-no-lowopacity]] explicitly allows monochrome typographic marks (✓ ✗ → ★); the ban is COLOUR pictographs. "10 dots on the cover" → miscount, code says `n={9}` everywhere. "Add gradients to the sprite" → it is deliberate flat pixel art (`shapeRendering="crispEdges"`). "Delete the speech lines" → HEY JARVIS! / TO CARTHAGE! etc. are Alex's canonical lines from reel 33. "Cut the text" → a carousel is a reading surface; deleting DUPLICATION is right, deleting SUBSTANCE is not.
- ⭐ **The single highest-value catch, and the critics under-diagnosed it:** they reported "mast impales Ben's head", "Kate's discs sliced", "Mia's chips clipped" as separate prop-collision bugs. Root cause was ONE thing: **the art scenes are authored in a 500x360 space but the card's art window is 378x301** — everything past x≈378 silently clipped. Fixed with a `ScaledArt` wrapper (`transform: scale(w/500, h/360)`), not by moving props. **When N critics report N collisions in one component, look for a coordinate-space mismatch first.**
- ⭐ **"The sprite has no contact shadow" (all 17 slides) was REAL but not for their reason.** `ContactShadow` existed in code — it used `rgba(6,10,22)` on a `#0E1626` panel = dark-on-dark = invisible. Added a `dark` variant (near-black) for panel interiors; keep the soft variant on cream. Then a second real bug surfaced: feet landed ~23px ABOVE the floor line. Fixed with `FLOOR_Y` + `feetAt(size) = FLOOR_Y - size*0.92` (the Mascot viewBox has ~8% empty below the legs) as the single source of truth; sprite tops and shadows both derive from it. `IdeEnv`/`C1Frame` take a `floorY` so the shorter CTA panel gets its own.
- **Also real and fixed:** invisible slate stat bars (SLATE fill on a 0.4-slate track = 1.7:1 → solid `#141E33` track + lighter fill); stat axes that read as MEASURED outcomes (REACH/RECEIPTS/COST/BUGS → TIRELESS/NERVE/SLEEP/EGO, and COST/BUGS also inverted the bar's meaning); the literal `X` in "by launching X" (a template variable on the hero line); POST2 missing the kicker entirely; the CTA offer contradicting itself in 3 places.

Six hires." is 4 words / 2 numerals and wins on mute. Only its subhead changed. ⭐ A gate that never says "the incumbent stays" is not a gate.

## ⛔⭐ THE HOUSE HIERARCHY — every carousel slide, every format (Alex, 2026-07-17: "make sure post 1 callback is hierarchical enough properly as well")
A slide needs FIVE distinct levels and each must be visually unmistakable. Post 1 v1 failed on all three counts below; fixing them is what "hierarchical" means here:
1. **KICKER** (pill, top-left) = wayfinding. `STEP 02 / 04 · MATCH` — position AND name in ONE pill.
2. **HEADLINE** (Fraunces) = the claim. 3. **SUBHEAD** (Inter) = the "which means". 4. **THE PANEL** = the proof visual. 5. **THE GIVE/RETURN STRIP** = the concrete.
- ⛔ **NEVER announce the same thing twice at two levels.** v1 had a `STEP 01 / 04` pill AND an `01 DIAGNOSE` badge inside the panel — two competing wayfinders. Merge into the kicker; the in-panel badge is deleted.
- ⛔ **THE TYPE SCALE *IS* THE HIERARCHY — it must be a fixed ladder, not per-slide taste.** v1 drifted 74/76/78/80/82/86 at random, which flattens the post. Locked ladder (`H1 size=` prop): **82 = bookends (cover / CTA) · 78 = chapter beats (problem / the loop) · 74 = the four steps.** A step slide may never out-shout the cover.
- ⛔ **Kill the dead band.** The gap between the subhead and the panel (~400-500) was empty cream on every step slide. It is now the **GiveReturn strip** — which fixes the hierarchy AND adds the concrete AND needed zero rescaling of the panel scenes. Reusable component `GiveReturn` in CarouselPosts.tsx, rendered via C1Frame's page-level `overlay` prop.
- **The give/return spine is now the ACCOUNT's language, shared across formats** — Terminal Brief step slides and Crew Cards exec slides both use YOU GIVE IT → IT RETURNS. That's what makes two different layouts read as one system.

**⛔⭐ A CAROUSEL IS A READING SURFACE — the reel "no text / minimal text" rules DO NOT transfer (Alex, 2026-07-17: the v1 crew post "doesn't have enough stuff describing what each does and how to hire them").** In a REEL the captions carry every spoken word, so on-screen text is duplication. In a CAROUSEL there is no VO and no caption track — **the slide IS the reading surface**, and a beautiful card carrying only a name + a role + stat bars says nothing. Each exec slide is now card-left + a real spec column right: **THE JOB** (3 concrete deliverables) · **YOU GIVE IT** (the exact input the reader hands over) · **IT RETURNS** (the deliverable back). Plus a dedicated "how you hire one" slide.
- **"YOU GIVE IT / IT RETURNS" is the gate-safe way to be concrete** ([[gate-the-how-in-scripts]] still binds): naming the INPUT ("one voice note + 3 posts you already liked", "3 competitor links") and the OUTPUT ("a shortlist, not a to-do list") is genuinely actionable and is NOT the copy-pasteable prompt. The prompt itself stays behind the padlock on the setup slide. Show the SHAPE, gate the CONTENT.
- Use **"it"** for the crew, never he/she — they are Claude in different roles, not human hires ([[crew-reel]] rule), and "YOU GIVE IT" reinforces that for free.

**⛔ CAROUSEL BUILD GOTCHAS (hit on round 2, 2026-07-17):**
- **`cd` inside a Bash call persists.** A `cd .../video/src` for a perl edit left the cwd there, so a later render wrote to `src/out/posts/` while I re-read the stale `out/posts/` file and "verified" an unchanged image. Always render from the video root (or use absolute paths), and if a render looks byte-identical after a real edit, suspect cwd before suspecting a cache.
- **BSD sed ignores `\b`** — `sed -E 's/^const (A|B)\b/export const $1/'` silently matched nothing and reported success. Use perl for word-boundary edits, and always verify the substitution count.
- **Card sub-rows must live in FLOW, not `bottom:`-anchored.** The pips row was positioned off the card bottom, which collided with the stats on 2-stat cards but not 3-stat ones. Anything whose position depends on a variable-length list goes inside that list's container.
- **Stamps need an explicit zIndex.** An `AUTO-REJECTED` stamp with no zIndex rendered BEHIND the `zIndex:10` resume it was stamping.
- **SVG `rotate(θ)` is CLOCKWISE, and a rotated child clips silently.** A boom-mic rod at `translate(34,12) rotate(42)` sent (0,196) to (−131,+146) = down-LEFT and off the viewBox, so only a stub survived. Wanted down-RIGHT → `rotate(-42)`. Sanity-check with (x,y)→(x·cosθ − y·sinθ, x·sinθ + y·cosθ) before rendering.
- **Keep a rotated prop as ONE group.** Rotating an arm and its capsule separately (different angles, different pivots) visually detaches them. Nest: `<g rotate><rod/><g translate(0,len)><head/></g></g>` so the join is structural.
- **First pass is a WIREFRAME here too.** Round 1 shipped small heroes floating in near-empty panels — Alex: "each of the scenes need to be a lot more detailed." The [[reel-overhaul-stage]] detail floors (≥3-4 layers, alive backgrounds, dressed sprite, environment not void) apply to STATIC carousels identically. Round 2 fix = a real rendered ENVIRONMENT per scene (IDE rail + tab strip + god ray + floor for C1; corkboard/desk/window room for C2; potion-shelf workshop for C2 beat; sidebar+tiles+chart dashboard for C4; drafting title-block + legend + dimension lines for C6) + margin satellites, keeping ONE hero.
- **C1Frame children are PANEL-LOCAL (0..panelH), same trap as the reels.** A CTA pill placed at page-y 1084 inside the panel silently clipped. Fixed with an explicit `overlay` prop that renders at page level. Any page-level element MUST go through `overlay`.
- **Ground sprites BEHIND furniture** (desk/bench slab drawn over the legs), else they read as standing ON the table.
- **Sprites float** unless a `ContactShadow` sits exactly at the foot line (`top + size*0.92`).
- Recurring overlap bugs to check every render: speech bubble vs. window, sprite vs. chart, pull-quote vs. body text, title-block vs. handle. Render and LOOK at every slide; do not trust the layout math.
