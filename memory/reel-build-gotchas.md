Two traps that silently break scene layout/timing in the `matchtern-longform/video` Remotion reels ([[video-editing-toolchain]]). Both cost a full render+inspect cycle each on reel 38 ([[vault-reel]]) — check them BEFORE the first still.

**⛔ Scene bodies render INSIDE `<Panel>` → coordinates are PANEL-LOCAL (0..792), not screen (0..1920).** `Panel` is `position:absolute; left:34; right:34; top:384; height:792; overflow:hidden`. A scene body's `<AbsoluteFill>` fills the Panel, so every `top:` is measured from the panel top and anything `> ~792` is CLIPPED (invisible). Symptom: the top half of a scene renders, the Mascot/badges/lower rows just vanish. Usable vertical band ≈ 210–780 local (ScreenHead title occupies ~55–200). The CTA scene is the exception — `ClockCTA` renders OUTSIDE the Panel, so it uses true screen coords (top ~366–1050).

**⛔ `over(f, start, dur, ease?)` takes FRAMES, not seconds.** It's `interpolate(f,[start,start+dur],...)`. Writing `over(lf, 6.6, fr(0.7))` means start=6.6 FRAMES (0.22s), not 6.6s — so the element pops in almost immediately instead of at 6.6s. ALWAYS wrap the start in `fr()`: `over(lf, fr(6.6), fr(0.7))`. (The `dur` is usually already `fr(...)`; the bug is forgetting it on `start`.) Symptom: staggered reveals all fire at once / far too early. Grep the new body for `over(lf, <bare-number>,` before rendering.

Also: to make a header/hero element visible on FRAME 0 (mute scroll-stop), you cannot use a plain `over(lf,0,...)` for its opacity (that's 0 at f0) — render it solid and animate only a small translateY settle, or floor the opacity.

**⛔ CLONING A REEL CHASSIS carries the OLD reel's baked text in SHARED components (ERASE built off the VAULT chassis, 2026-07-10).** When you copy `ClaudeXReel.tsx` → `ClaudeYReel.tsx` and swap only audio/words/L/scene-bodies, the SHARED overlay components still render the previous reel's copy and MUST be grepped + swapped: (1) `ScreenHead`'s per-scene status pill (VAULT hard-coded "FABLE 5 · 3 DAYS FREE" / "NOW PAID" — a DEADLINE pill that reappeared on 5 scenes of a no-deadline privacy reel = auto-blocker); (2) the CTA guide card's 3-check contents (VAULT: "the good calls prompt / rule back-solver / vault file" showed up on ERASE's endcard); (3) the CTA keyword string (`const kw = "VAULT"`) + big clay keyword text + guide title. PRE-RENDER GREP after any chassis clone: `grep -niE "vault|days free|now paid|good calls|back-solve|<prev-keyword>"` on the new file and swap every non-comment hit. The adversarial ship-critic caught all three, but they're mechanical — grep them out before the first render.


**⛔ DELIVERY ENCODE (HARD, 2026-07-10):** Remotion's h264 output tags color as bt470bg and leaves moov at the end — QuickTime/Preview REFUSE to open it ("not compatible") even though ffmpeg decodes fine. EVERY delivery encode must include: `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -movflags +faststart` (plus the usual libx264 high / yuv420p / crf 18 / AAC 256k). Verify with qlmanage -t (Quick Look thumbnail = macOS pipeline accepts it).

**⛔ SFX TRUNCATION CLICKS = 'metronome' (HARD, 2026-07-10):** any <Audio> whose FILE is longer than its <Sequence> window gets HARD-CUT at the window edge -> an audible click/pop; with many Sfx windows this reads as a metronome ticking through the whole reel (Alex flagged twice). The Sfx helper MUST apply a fade envelope: volume={(f)=>{const total=fr(dur); return v*Math.min(1,f/2)*Math.min(1,Math.max(0,(total-1-f)/6));}}. Same for looping OffthreadVideo audio (loop restarts pop every loop) — play ONE audio pass with a fade then mute. Check library mp3 durations (lib_typing=26s!, digital-loading=16s, sand-steps=10s) — never assume they are short.

**⛔ CLICKY MUSIC BEDS = 'metronome' pt.2 (HARD, 2026-07-10):** seo_music.wav (73 sharp transients/107s) and ados_bed_loud.wav (53/50s) both have percussive plucks; at bed volume under VO only the TRANSIENTS stay audible -> reads as a bare ticking metronome (Alex flagged 3x; lowpass does NOT fix it, the hits are low-freq). Fix = transient-free synthesized bed: public/bed_pad.wav (4 detuned sines lowpass 900 + pink-noise wave-wash lowpass 420, slow sin-volume swells, loudnorm I=-30; play at volume ~0.9 ducked to 0.5 at CTA). Transient-check any new bed before use (25ms peak-envelope, spike>1.6x local median).


**⛔ METRONOME/CLICK — REAL CAUSE (Alex, 2026-07-11, RESOLVED): it was BAKED INTO ALEX'S VOICEOVER RECORDING (a click in his mic/room), NOT the SFX or the music bed.** The v10-v15 theories (SFX truncation, clicky music transients, synth-bed) were RED HERRINGS — do NOT strip SFX or swap the music to chase a perceived tick again. Alex has fixed it at the recording source. KEEP the fade-envelope Sfx helper (good hygiene) but ADD SFX GENEROUSLY.
**⭐ MORE SFX = MORE ENGAGEMENT (Alex standing preference, 2026-07-11):** layer MANY varied SFX from ~/Downloads/sfx-library, especially DENSER TYPING (stack multiple mac-type/keyboard hits per typing moment, not one), plus pops/dings/whooshes/sparkles/shutters/cash-register/etc on every state change. Under-scoring reads as cheap; a busy, content-matched soundscape is the goal. Pull fresh variety each reel; don't reuse the same 5.

- **⛔ ANIMATED METERS/GAUGES that "GLITCH / flicker 1↔2 lines" (Alex flagged reel 44 H4 gauge, 2026-07-12):** a ring/bar meter that lights ticks or segments via a per-frame BOOLEAN + a bright "just-crossed" SPIKE (e.g. `lit = pct>=x; justLit = 1-(pct-x)/6; col = justLit>0.15 ? "#F6D98A" : ...`, plus an outward `+justLit*9` jump) reads as flickering extra lines popping in/out as the frontier sweeps. FIX: light each tick with a SMOOTH monotonic eased ramp (`litAmt = clamp((pct - x + 3)/6, 0,1)`), pick colour by `litAmt>0.5`, no bright-yellow pop, no outward jump. ALSO: a big number with a `translateX(jitter)` "vibrate while racing" transform reads as glitchy text — drop it, keep only a scale pulse, and add `fontVariantNumeric:"tabular-nums"` so changing digits don't reflow/shift. And motion-trail ghost knobs behind a racing marker can look like stray dots — keep them faint (opacity ≤0.25) or cut them.
- **⛔ TEXT CENTERED INSIDE A RADIAL/RING GAUGE COLLIDES WITH THE ARC + MARKER (reel 44 H4, Alex flagged 3x "text overlapping", 2026-07-12 — I MISSED it twice because the number LOOKED cleanly centered):** a sublabel (e.g. "was 52% · ATS screener") placed in the vertical-center stack of a ring gauge gets (a) pinched on both ends by the two arc RAILS (at that y the ring passes through x=cx±√(R²−dy²), right where the outer words sit), and (b) run over by the TRAVELLING MARKER KNOB, which sweeps down to the lower-right as the fill climbs and lands on the text at high %. A still of the LOW-fill frame hides it — you must check the HIGH-fill frame (marker at its lowest travel) and watch for the rails. FIX: pull any sublabel OUT of the ring's mid-band — drop it into the ring's OPEN bottom gap (below the arc's lower tips + rounded caps, below the marker's lowest y) or fully below/outside the gauge. Keep only the big number + label in the ring center. Same hazard for a needle/knob on any circular meter.
- **⛔ AGENT-AUTHORED SCENES: 3 recurring render-crashers to grep after EVERY splice (reel 51 SKILLS, 2026-07-12):** (1) **un-clamped "pop/flash" opacity** — `const pop = Math.max(0, 1 - (lf - fr(X))/9)` is HUGE before frame X (e.g. 8.6 at lf=0), so a flash/white overlay driven by it (`opacity: pop*0.22`) pins to full and WASHES the whole scene the wrong colour for seconds. Guard it: `lf < fr(X) ? 0 : Math.max(0, 1 - (lf - fr(X))/9)`. This washed the SKILLS Matrix hook cream. (2) **invalid Easing names** — `Easing.quart` / `Easing.quint` / `Easing.expo` / `Easing.circ` do NOT exist in Remotion (only quad, cubic, sin, circle, exp, poly, bounce, back, elastic, bezier, ease, linear, step0/1, in/out/inOut) → runtime "easing is not a function". Grep `Easing\.(quart|quint|expo|circ)`. (3) **descending/equal ramp ranges** — `ramp(lf, 24+i, 20)` (a>b) or `ramp(lf, 22+(i%3), 24)` that hits [24,24] → "inputRange must be strictly monotonically increasing". After any multi-agent splice, still-render EVERY scene (a crashing scene throws only on its own frames), and grep for these three. Also: whisper bakes "Claude"→"Cloud"/"Clod" mishearings into words_*.json captions — fix them before render.
- **⛔ `background:` + `backgroundImage:` IN THE SAME REACT STYLE = TRANSPARENT element (brick castles, 2026-07-13):** setting `style={{ background: "linear-gradient(...)", backgroundImage: "repeating-linear-gradient(...)" }}` — the `background` SHORTHAND sets background-color to transparent AND background-image to the gradient, then the longhand `backgroundImage` OVERRIDES the image with the (transparent-striped) pattern. Result: transparent element showing only the brick lines, with the sky/scene visible THROUGH it. Alex flagged the Mario castles rendering see-through. FIX: use `backgroundColor: "<solid>"` + `backgroundImage: "<pattern>"` (solid fills, pattern overlays), OR put everything in one `backgroundImage: "<pattern>, <gradient>"` with the gradient as the LAST (bottom) layer. Never pair a `background` gradient with a separate `backgroundImage` pattern. Grep textured props (castle/brick/ground/QBlock) for this pairing.
- **⛔ `npx tsc` IS A DECOY on this box — render is the ONLY validation gate (2026-07-13):** there is no local `typescript` in `matchtern-longform/video`, so `npx tsc --noEmit` runs a squatting package that prints "This is not the tsc command you are looking for" and EXITS 0. A "clean" tsc means NOTHING — it never type-checked. Undefined identifiers (e.g. an agent using `<Firework/>` it never defined) compile fine and only throw `ReferenceError` at RENDER, on the specific frames that execute them. After ANY splice/edit, validate by rendering a DENSE frame sweep (~30 frames spanning every scene), not by tsc, and not by one still per scene.
- **⛔ ramp() is NOT a lerp (XRAY remake, 2026-07-11):** parallel scene-author agents read `ramp(f, a, b)` as "animate f from a to b" — it actually maps f FROM input range [a,b] TO 0..1, so a>b throws `inputRange must be strictly monotonically increasing` at RENDER time (compiles fine; stills on that scene crash). When briefing scene agents, state it explicitly or tell them to use plain lerps (`a + t * (b - a)`); after any splice, still-render EVERY scene, not just one.
- **⛔ HOOK-HEADER OCCLUDED BY THE SCENE'S OWN FOREGROUND (reel 68 CHART, 2026-07-19):** the shared `ScreenHead` (the big mute-readable top-third hook line) was at `zIndex: 46`, but cinematic scene bodies put a foreground DOF plane (crane hook, I-beam, blurred silhouettes — "PLANE 6") at `zIndex: 120` INSIDE the same `<Panel>` stacking context. Result: the foreground paints OVER the header text (CHART's "AGENT" was hidden behind a black beam), on EVERY scene that has a high-z foreground. The header is chrome and must be the topmost legible element — raise `ScreenHead`'s zIndex above any body foreground (used 175; body foregrounds run ~120-160, the between-scene flash is z200 outside the panel so it still washes over, which is fine). Fix once in the shared component and all scenes are fixed. When authoring a cinematic scene with a foreground plane, cap that plane's z BELOW the header, or bump the header. Grep scene bodies for `zIndex: 1[0-9][0-9]` foreground layers vs the header z.
- **⛔ A SPRITE THAT SLIDES LEFT-RIGHT AT CONSTANT SIZE READS AS "SKATING / MOVING UNDER" OTHERS (reel 68 CHART walker, Alex flagged, 2026-07-19):** a background worker oscillating `x = base + sin()*swing` at a FIXED size/depth looks like it floats sideways through the scene and clips past other sprites. A perspective floor demands depth-correct motion: make it a slow ping-pong in DEPTH (triangle wave → `t` far↔near), scale size with depth (`150*S(t)`), and let x RIDE the aisle-convergence line so it moves toward the vanishing point as it recedes (`x = CX - (HALF(S)+k*S)`), facing its travel direction (flip). Keep its z below all near sprites so it can never clip through them. Pairs with [[reel-sprite-grounding-law]].
- **⛔⭐ A STATIC-FEELING HOOK is a CONCEPT problem, not a polish problem (reel 68 CHART C1, Alex rejected the opening 3x, 2026-07-19):** Alex kept calling the opening "too static... just them standing on a conveyor belt" AND "it doesn't represent what's being spoken (you only use 10% of Claude's brain)." Polishing the same factory-hall never fixed it. What worked: a **judge-panel design workflow** (4 diverse visual devices for "10% of a brain" -> score on {reads-on-mute, dynamism, cinematic-not-infographic, buildable} -> merge the winner). It picked **TEN NUMBERED BAYS, ONE LIT** — a countable "1 of 10" denominator (stencilled 01..10 lintel plates) is the only device that lands "10%" in <1s on mute WITHOUT a chart. Lessons: (1) when the HOOK keeps getting rejected, the fix is a new CONCEPT/metaphor tied to the exact VO words, generated adversarially, not another polish pass on the old one; (2) the header must quote the VO ("YOU ONLY USE 10% OF CLAUDE'S BRAIN"), not paraphrase; (3) a **countable literal** (1 of 10 doors) beats an abstract ratio (a lit fraction of a wall reads as a heatmap/infographic — the exact failure that gets these killed); (4) SPREAD the countable elements across the frame width — a colonnade clustered in the left third leaves a dead-empty right half and the reveal only fills the cluster; push the vanishing point right so all N are countable and the ignition fills the whole frame.
- **⛔ A "camera-LOCKED reveal" reads STATIC on the motion metric even when lots is happening (reel 68 CHART C1, 2026-07-19):** a bay-by-bay ignition wave (small lamps + small sprites rising + thin threads) is very watchable but scores ~1.2-2.0 on `motion_audit.py` (whole-panel mean |delta| under-counts many small movers, esp. under a locked camera). If a phase is camera-locked, add a CERTIFIED big mover: a warm **power-SWEEP band** (~480px wide, screen-blend, travelling ~16px/frame across the panel) + a gentle camera **push+pan following the action** lifted the locked buckets 1.2 -> 4.8 with zero added clutter (ambient light, not new objects). Don't chase the metric past ~4 (memory [[reel-motion-hierarchy]]: over-tuning -> "too chaotic"); the goal is "no dead bucket + felt momentum," and a brief calm bucket (~3) is fine on the exact beat you want the viewer to *count/read* something.
- **⛔ VO TAIL CUT OFF: the composition was SHORTER than the voiceover (reel 68 CHART, Alex "it just cuts on follow", 2026-07-19):** `durationInFrames` (922 = 30.73s) was < the VO's last voiced sample (31.18s), so the CTA "...follow and comment CHART" chopped at "follow". The whisper CAPTIONS said CHART ended at 30.61s but the ACTUAL wav ran to 31.18 — trust the wav's RMS tail, not the caption times. Fix: extend `durationInFrames` past the wav end (940 = 31.33s), and bump any `CUT`-derived constants (CLOCK_START/reward beats) so they still land near the real end. The last scene auto-extends because it renders for all `frame >= Lf[last]`. Always check `wav_dur*fps <= durationInFrames` before delivery.
- **⛔ CTA-BEAT ×6 BLUR + 60% SCRIM = "no background detail" (reel 68 CHART C6, Alex flagged, 2026-07-19):** a rich environment behind a CTA lockup, blurred at ~6px and dimmed 60%, turns to indistinct mud and reads as "you didn't put detail in the background." Cut the DOF blur to ~3px and the scrim to ~0.44 so the foundry/workshop still READS behind the card (the CTA still pops via its own backing bloom + the card's dark fill). Bonus: flat black "agent silhouettes" tending a line read as chess pawns — use dim real `<Mascot>` sprites (`filter: brightness(0.62)`) instead, which adds the detail AND fixes the pawn look. This also fixed the motion metric (a legible moving workshop scores 9-10 vs a blurred one ~0). Pairs with [[reel-declutter-single-hero]].
